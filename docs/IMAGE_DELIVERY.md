# PNG/JPEG → оригинал и optional OCR → Obsidian

Dev-версии: capture-core/API 0.2.0, расширение 0.4.0, Connector 0.2.0.
Проверяемая платформа: desktop Zen/Linux и Obsidian. Публикации и подписанной
установки нет. ASR и его лёгкий профиль base не изменены.

## Запуск

```sh
python -m pip install -e '.[images]'
python -m unimem_api --data-dir /absolute/private/unimem-data
```

Этого достаточно для сохранения изображения без OCR. Для распознавания нужен
системный Tesseract с `eng` и `rus` language data и тот же сервер с `--image-ocr`.
Например, в Debian/Ubuntu системные пакеты — `tesseract-ocr`,
`tesseract-ocr-eng`, `tesseract-ocr-rus`. Данные и модели автоматически не скачиваются.
Pillow проверяет декодирование; оригинал не перекодируется и не очищается от EXIF.

Сборка расширения и установка в отдельный профиль описаны в
[browser guide](BROWSER_DELIVERY.md). Сборка и настройка самостоятельного плагина —
в [Connector README](../clients/obsidian-plugin/README.md) и
[pairing guide](OBSIDIAN_DELIVERY.md). Browser token и receiver token различаются.
UniMem не открывает директорию vault; единственный писатель — Connector.

В Connector явно включите **«Разрешить PNG/JPEG-вложения»**, сохраните конфигурацию,
проверьте подключение и включите приём. Миграция старых настроек оставляет это
разрешение выключенным. Дождитесь первого poll или нажмите «Получить сейчас»:
получатель зарегистрирует возможность принимать v2 для своего destination.
Отключённый плагин не импортирует файлы; объявленная серверу возможность описывает
последнюю регистрацию, а не присутствие плагина онлайн. Поэтому queued не означает imported.

## Действия в Zen

1. Откройте существующую страницу управления UniMem и раздел изображения.
2. Выберите или перетащите один локальный PNG/JPEG. Проверьте предпросмотр.
3. Нажмите **«Сохранить изображение»** либо **«Извлечь текст»**. Первый режим
   не запускает Tesseract, не описывает сцену и не делает смысловой анализ.
4. До окончания upload закрытие страницы может прервать передачу. После
   подтверждения приёма сервер работает независимо; «Обновить статус» читает
   прежний operation ID. Неопределённый POST сначала проверяется GET; явный повтор
   использует те же параметры и ID только при подтверждённом отсутствии операции.
5. Откройте результат. Проверьте отдельные upload/operation/OCR состояния,
   текст, изображение, destination и размеры одной заметки и одного оригинала.
6. Явно нажмите **«Отправить в Obsidian»**. Обновите статус доставки. Только
   `imported` означает ACK после проверки обоих файлов. Конфликт/ошибка/неоднозначность
   остаются видимыми. Бесконечного polling и оценочных процентов нет.

В заметке — локальный источник, время, capture/content IDs, изображение по
относительной ссылке, способ обработки и отдельный буквальный OCR-текст.
Текст OCR не исполняется и не создаёт дополнительные embeds/HTML. Оригинал может
содержать EXIF и другие metadata: в vault переносится именно этот файл.
Одиночный `.md` не является полным image-export; для этого сценария он не предлагается.
Прежние YouTube/аудио `.md` exports сохранены.

## Честные ограничения

| Граница | Лимит / поведение |
| --- | --- |
| Формат | Статический PNG/JPEG; подпись + структурный header + полное decode/verify |
| MIME | Пустой или octet-stream разрешает определение по байтам; противоречие отвергается |
| Оригинал | 16 МиБ; отдельно до 40 миллионов пикселей |
| Image worker | Один процесс, 60 с wall/CPU budget, 1 ГиБ address space; очередь до 8 |
| Tesseract | Существующий адаптер, eng+rus, OEM 1 / PSM 3, 30 с; до 20 млн пикселей |
| Markdown | 1 МиБ UTF-8, без обрезания |
| Пакет | Одна заметка + один PNG/JPEG, вместе до 17 МиБ |
| HTTP чтение | JSON до 6 МиБ + 16 КиБ; binary до 16 МиБ, 30 с; redirects запрещены |
| Клиентская история | До 50 ссылок на операции; байты в browser storage не сохраняются |

OCR: `not_requested`, `text`, `empty`, `skipped` — разные результаты. `empty`
означает, что выполненный OCR не вернул текст; это не доказательство отсутствия текста.
`skipped` означает известное ограничение, а не успешное распознавание. Ошибка OCR
делает operation failed; upload сохраняется, существующий capture lifecycle остаётся
PROCESSING без вымышленного complete ContentObject. Готового пакета в этом случае нет.
Повторный просмотр, render и доставка OCR не запускают. Уже готовые результаты
читаются сервером без включённого OCR.

## Протокол и восстановление

V1 остаётся strict Markdown-протоколом; v2 имеет отдельные маршруты. Старый Connector
не увидит пакет как обычную заметку, не импортирует только Markdown и не сможет
подтвердить его старым ACK. Несовместимость вложений не препятствует импорту v1.
Browser показывает необходимость обновления/разрешения вложений до Send.

До HTTP acceptance сервис фиксирует snapshot и обязательный manifest: asset ID,
MIME, размер, SHA-256 и безопасное относительное имя. Повтор возвращает ту же запись.
ACK v2 связывает весь manifest и Markdown через package SHA-256. Бинарный endpoint
проверяет receiver destination + delivery + asset; raw ref/hash не служит доступом.
Формула digest и wire fixtures: [Python](../src/unimem_api/obsidian_contract.py),
[v1](../fixtures/obsidian-delivery-v1.json), [v2](../fixtures/obsidian-delivery-v2.json).

Connector сохраняет намерение на оба детерминированных пути, проверяет оба пути,
загружает и проверяет вложение, создаёт/читает его, затем создаёт/читает заметку,
повторно проверяет вложение, сохраняет результат и отправляет ACK. Файлы — соседи
в настроенном inbox, в том числе вложенном. Межпакетной дедупликации нет.
Посторонний существующий файл конфликтует даже при совпадающем hash.

После crash проверять собственный файл разрешает только сохранённый journal.
Отсутствующий файл со статусом creating/written неоднозначен: он не восстанавливается.
Два файла не образуют атомарную транзакцию. Остатки не удаляются; новые имена с
суффиксами не создаются. Journal/save failure откатывает неподтверждённую память;
очередь сохранения остаётся рабочей. Истёкший lease, unload или смена настроек
останавливают дальнейшие записи после await. Принятый ACK с потерянным ответом
сверяется с серверным receipt. После imported файлы принадлежат пользователю:
его изменения, перемещения и удаления не отменяются.

При `ambiguous` сохраните data.json и файлы для ручной проверки. Не удаляйте журнал
ради повторного импорта и не переносите его в другой vault. Внешняя гонка изменения
файлов и утрата самого журнала остаются ограничениями; подробности в
[ADR-029](ADR/ADR-029-image-attachment-delivery.md).
